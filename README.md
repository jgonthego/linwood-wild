# Linwood Wild

Static site listing every wildlife species you could possibly see around Linwood, NJ,
rated **Likely / Possible / Rare** from real records:

- `scripts/fetch_possible.py` counts GBIF occurrence records since 2000 (eBird EOD, iNaturalist research-grade,
  museum specimens) in rings of 2 km, 8 km and 15 km around a fixed center point (mainland only; the barrier islands
  are cut off along the back-bay line in `scripts/zones.py`), applies the likelihood rules, drops ocean-only
  taxa, and adds names, open-licensed photos and Wikipedia summaries from iNaturalist.
- `scripts/fetch_habitat.py` summarises NJDEP Land Use/Land Cover 2015 around the point (rounded % only).
- `scripts/fetch_sounds.py` adds one openly licensed iNaturalist recording per bird (trimmed with ffmpeg).
- `scripts/fetch_gallery.py` builds `data/gallery.json`: for every bird, up to 4 photos each from research-grade iNaturalist
  observations annotated **Sex = Male** (term 9 / value 11), **Sex = Female** (9 / 10) and **Life Stage = Juvenile** (1 / 8),
  ordered by votes, photo licence CC0 / CC BY / CC BY-SA / CC BY-NC only, one photo per observation, dead birds and
  feathers/nests excluded. A label is shown only when the observation carries that annotation (vote score >= 0); Adult is
  added when the same observation is also annotated Life Stage = Adult. iNaturalist has no annotation for pose (flight,
  perched, back, front) or breeding plumage, so those are **not** labeled: the extra photos are the species' curated
  iNaturalist taxon photos, unlabeled. Other groups get the taxon photos as a multi-photo gallery.
- `scripts/fetch_wiki.py` stores each bird's Wikipedia lead + Description section (`data/wiki_desc.json`, CC BY-SA, free
  MediaWiki API). `scripts/build_traits.py` turns that and `data/traits_curated.txt` into `data/traits.json`:
  - **"How to tell male vs female"**: verbatim Wikipedia sentences that mention male/female/sexes *and* appearance words
    (sentences about nests, eggs, song, weight etc. are skipped). Birds without such a sentence get no note.
  - **Describe-a-Bird traits**: see "Trait data quality" below.
- `build.py` builds `docs/`; GitHub Actions deploys to Pages and refreshes the data monthly (galleries, Wikipedia text
  and traits are incremental: committed data persists and only species new that month are fetched; a bird not in the
  curated table gets Wikipedia-parsed traits flagged `q: "wiki"`).

## Trait data quality (Describe-a-Bird)

- `data/traits_curated.txt` is a **hand-written** table for all 306 birds (approx. length in cm, main colours of the adult
  male/adult, extra colours of females/immatures, markings, behaviour, habitat). It was written from standard field-guide
  knowledge, not copied from any one source, and is a search helper, **not** an authority.
- Spot-checks (`data/traits_report.json`, regenerated by `build_traits.py`): curated length vs the length parsed from
  Wikipedia (255 birds have one) — 5 differ by >35 %, and all 5 are parser errors on the Wikipedia side (wingspan or
  subspecies numbers picked up), not table errors; curated colours vs colour words in the Wikipedia description — 81 birds
  have a curated colour the article's Description section doesn't name, mostly minor shades (buff, rufous, olive); these
  were reviewed by eye and left as is.
- Behaviour/habitat tags are coarse (feeder, ground, trunk, flyover, soaring, swimming, diving, wading, hovering, flocks,
  night; yard, woods, marsh, water, field, beach) and reflect typical behaviour, not every possibility.
- Matching is keyword + synonym based (red/crimson/scarlet, rufous/rusty/chestnut/cinnamon, streaked/streaky/striped,
  crest/crested/tufted, chest→breast, crown→cap …), with colour+part pairs ("red cap", "streaky chest") scored as pairs,
  a size check against the length, and a prior favouring Likely birds recorded in the current month. All in the browser.

## Bird journal

Stored only in the visitor's browser: entries in `localStorage` (`lw-journal-v1`), photos (resized to 1280 px JPEG) in
IndexedDB (`lw-journal`). No GPS, no server, nothing published. Export/import as JSON (optionally with photos) or CSV.

The center point is never published: it lives in the git-ignored `data/home.private.json` locally and in the
`HOME_LAT` / `HOME_LNG` repository secrets for the monthly refresh.
